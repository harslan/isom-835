01 / The fair split

First, a trivia night

SHAP rests on an older question from game theory. A team wins a prize together. How much of it did each player earn? Lloyd Shapley answered that in 1953, and the answer carries his name: the Shapley value.

Meet the team. Tap a player to seat them at the table or send them to the bench, and watch the score.

90

The catch: credit depends on who sat down first

Seat the full team one player at a time. Pay each player whatever the score went up when they arrived. That raise is called a marginal contribution. Try a few seating orders.

Same team, same 90 points, different paychecks every time. No single order is fair. Shapley's move was simple: use every order, then average.

Seating orderAliBeaCy

Those averages are the Shapley values: Ali 35, Bea 40, Cy 15. They add up to exactly 90.

Look at Cy. Alone he scores only 10, yet his fair share is 15, because he knows things nobody else at the table does. Ali scores 40 alone but earns 35, because some of what he knows, Bea knows too. A fair split pays you for what you add to the team.

05 / Why this split and no other

Four rules a fair receipt has to keep

Plenty of methods can hand out credit. Shapley proved that his average is the only one that keeps rules like these together. The checks below are live, wired to the sliders above.

Rule 1 · additivity

It adds up

Base value plus every line equals the prediction. No credit goes missing and none is invented.

Rule 2 · the dummy rule

No free riders

A feature that never changes the prediction gets exactly zero. This model ignores shoe size.

Rule 3 · symmetry

Equal work, equal credit

If two features always help by the same amount, in every possible team, they get the same share. Names and column order never matter.

Rule 4 · consistency

More work, never less credit

If you change a model so that it leans on a feature more, that feature's credit can never go down. Several older methods break this rule.

07 / Limits

Read the fine print

A receipt is honest about what was charged. It says nothing about whether the prices were right. Three limits to keep in mind.

TERMS

1. THIS EXPLAINS THE MODEL, NOT THE WORLD

"Income added 24 points" means the model leans on Maya's income. It does not mean a raise would make Maya more likely to repay. That is a cause-and-effect question, and SHAP does not answer it.

2. OVERLAPPING FEATURES SHARE THE CREDIT

If two features carry the same information, like income and home value, the split between them can look odd. It is Ali and Bea's shared history knowledge again.

3. BIG MODELS NEED SHORTCUTS

Five features make 120 orders. Thirty features make more orders than there are stars in the observable universe. Real tools estimate instead: KernelSHAP samples teams, and TreeSHAP computes exact values quickly for tree models.

The base value also depends on which applicants you average over. Change the crowd and the receipt changes.

08 / Check yourself

Three quick questions

The whole idea in one breath

Treat the features as teammates. Pay each one its average contribution across every order they could arrive in. Hand over a receipt that adds up to the prediction.
